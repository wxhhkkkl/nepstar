# 后端更新操作说明

适用：腾讯云 Linux 服务器，Python 3.11+，直接运行 FastAPI/uvicorn，默认端口 8000。

## 日常更新：执行一条命令

将新后端代码更新到服务器原来的 `backend` 目录，保留服务器已有的 `.env`，然后在该目录执行：

```bash
bash deploy.sh
```

不需要手动激活虚拟环境、安装依赖或查 PID。脚本从自身位置确定项目目录，识别当前目录下的 `app.main:app` 单进程 uvicorn 服务，安装依赖、检查配置/数据库结构后，平滑停止旧服务，启动新服务并等待健康检查。成功时显示“更新成功”和日志路径；关闭网页终端后服务仍会运行。

脚本会保留服务器的 AI 启停配置。若环境中的四个 `AI_CONSULT_*` 开关明确设为 false，后台总开关仍受这些配置限制；部署命令不会自动解除限制。

AI 咨询设置中的六项额度（入口频率、每日回答次数、提问频率、每日 token 预算、提问字数和同时生成数）统一使用 `0` 表示不限制，正数表示对应上限。暂停服务请使用“前台 AI 咨询开关”。升级此规则时需同步更新后端、管理端及报告端；已有的零值会按不限制生效，无需迁移数据库。

如果端口不是 8000，例如 8001，后续各命令都使用相同端口：

```bash
bash deploy.sh --port 8001
```

## 常用操作

```bash
# 只查看更新计划；不联网、不写文件、不操作服务，本机也可以运行
bash deploy.sh --dry-run

# 安装/检查依赖，读取数据库结构并检查连接；不重启服务
bash deploy.sh check

# 查看当前项目服务和健康检查结果
bash deploy.sh status

# 查看最近一次成功部署的服务日志；Ctrl+C 退出查看，不停止服务
bash deploy.sh logs
```

`check` 会连接服务器 `.env` 指定的 MySQL/MongoDB，仅检查元数据、执行 SELECT 和 ping，不读取报告正文，不调用模型。检查最长 90 秒；启动健康检查默认最多 60 秒。只有 `--dry-run` 完全不联网。

## 第一次使用

1. 确认服务器上传了 `deploy.sh`、`scripts/deploy_backend.py`、`scripts/deploy_check.py`、更新后的 `requirements.txt`，以及本次后端完整代码。保留服务器 `.env`，不要用本机文件覆盖；服务器专用 JWT 密钥要求至少 32 字符。
2. `.env` 中 `NEPSTAR_DATABASE_URL` 必须显式指向 `mysql+aiomysql://…/nepstar`；地址/密码仍只保存在服务器配置中。通用 `DATABASE_URL` 可以指向报告使用的其他 MySQL 库。
3. 执行 `bash deploy.sh check`。若缺少表、字段或索引，会明确列出并停止；先完成首次上线的数据库备份和经核对的专用迁移。当前 AI 表涉及 006/007/008，不能直接使用默认 `alembic.ini`，也不能用 `stamp` 掩盖缺失结构。**本脚本不执行数据库迁移或创建表**。以后更新如含新结构变更，同样先处理对应迁移。
4. 检查通过后执行 `bash deploy.sh`。无需手工停止当前服务：脚本可接管同目录、同端口的普通单进程 uvicorn。若原服务由 systemd、Supervisor、Docker 等管理，请继续通过原管理器更新；不要同时运行两个启动工具。热更新、多 worker 或其他目录的服务会拒绝接管。

正常启动会执行项目现有的菜单/管理员权限初始化逻辑，因此菜单可能随新版本出现。脚本的 `check` 阶段只导入模块定义，不执行这些启动逻辑。请在**云服务器实际项目目录**运行部署；本机服务目前连着云数据库，不应用来演练正式部署。

## 出错时怎么看

- **依赖安装或部署检查失败**：脚本尚未发送停止信号，旧进程仍运行；修复提示后重新执行。已上传的源代码不会被脚本自动回退。
- **端口被其他项目占用**：脚本拒绝停止未知进程；核对目录和端口，不执行按端口强杀。
- **旧进程退出超时**：只发送 SIGTERM，不发送 SIGKILL。先执行 `status` 核对，等原进程结束后再执行部署。
- **新服务启动失败或超时**：旧服务可能已经停止，脚本以非零状态退出，显示本次日志路径；不会显示“成功”或自动降级数据库。先看该日志、修复配置/代码，然后重新执行 `bash deploy.sh`。`logs` 默认是最近一次成功部署日志，失败时以错误提示中的路径为准。
- **需要恢复旧版本**：在保留 `.env` 和数据库的前提下恢复已确认兼容的后端代码，再运行本脚本。不要通过删表/降级数据库回退咨询记录。

运行文件存放在 `backend/.deploy/`：依赖环境按 Python/requirements 内容复用，日志按部署时间保存，权限默认仅部署用户可访问，Git 已忽略。脚本不会自动清理环境、日志、咨询记录或备份。日志可能包含应用异常信息，不要公开未脱敏原文。

这个脚本管理直接运行的服务，不配置开机自启动，也不更新 Nginx、管理端或报告端。服务器重启后，可在后端目录再次执行 `bash deploy.sh`。更新期间有短暂中断；健康检查通过表示该进程已响应，不替代线上报告、AI 回答、代理流式显示和手机验收。
