# Feature Specification: 单指标详情展示与只读数据边界

**Feature Branch**: `005-single-indicator-detail`
**Created**: 2026-09-20
**Status**: Implemented (mock/offline verified; live data acceptance pending deployment)
**Input**: 在现有 V2 报告系统详情页中打开单个指标详情；沿用已确认的疏朗、高保真设计；除 `nepstar` 库外，所有外部数据源只能读取，绝不修改。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从系统详情查看单个指标 (Priority: P1)

作为报告查看者，我在系统详情页点击一个指标项后，希望看到同一份报告、同一指标的名称、得分、状态和解读，并能返回此前的系统详情阅读位置。

**Why this priority**: 这是单指标详情的主路径；数据错配比缺少附加内容更严重。

**Independent Test**: 在一份包含“免疫力→淋巴结”的报告中点击“淋巴结”，核对详情得分与系统详情列表一致；返回后核对滚动位置。换一个报告或指标重复测试，结果必须随报告变化。

**Acceptance Scenarios**:

1. **Given** 一份已就绪且属于当前客户的报告，且指标已启用并映射到该报告，**When** 查看者点击系统详情中的指标，**Then** 打开该指标详情，名称、得分与同份报告的系统详情列表一致。
2. **Given** 查看者从系统详情某个滚动位置进入指标详情，**When** 点击顶部返回，**Then** 返回原系统详情页的原阅读位置，而非首页或页面顶部。
3. **Given** 已打开某指标详情，**When** 刷新或分享当前地址，**Then** 页面仍定位同一份报告和同一指标，不依赖先打开首页。
4. **Given** 指标不存在、未启用、不属于该系统或不在该报告中，**When** 请求详情，**Then** 不显示其他指标的数据或猜测结果，而显示可恢复的“指标不可用”状态。
5. **Given** 报告不存在、未就绪、客户不匹配或数据源不可用，**When** 打开指标详情，**Then** 沿用现有报告错误语义和页面状态，不出现白屏或演示数据。

### User Story 2 - 阅读真实趋势与行动建议 (Priority: P1)

作为报告查看者，我希望看到自己的历史检测趋势和后台维护的行动建议，而不是由设计稿或固定样例伪造的数据。

**Why this priority**: 健康报告必须严格区分真实历史、首次记录和缺失内容。

**Independent Test**: 分别使用有至少两次记录、只有一次记录、无建议的指标，核对趋势点、首次记录提示和建议区域的显示规则。

**Acceptance Scenarios**:

1. **Given** 同一客户的该指标有至少两次有效历史记录，**When** 打开详情，**Then** 按检测时间显示最近至多六次真实得分，并以真实日期或检测次序标识；当前报告包含在序列内。
2. **Given** 仅有本次一条有效记录，**When** 打开详情，**Then** 显示“本次为首次有效记录”，不绘制虚构折线。
3. **Given** 某份历史报告中没有该指标或得分无效，**When** 生成趋势，**Then** 跳过该记录，不补零、不拿其他指标替代。
4. **Given** 后台为该指标维护了解读与行动建议，**When** 打开详情，**Then** 展示对应文案；未维护时隐藏相应内容，不自动生成健康结论。
5. **Given** 详情正在加载，**When** 数据尚未返回，**Then** 显示与页面结构相称的骨架屏，避免大面积空白。

### User Story 3 - 维护单指标文案且保护外部数据 (Priority: P1)

作为指标维护人员，我希望在现有指标管理中维护单个指标的状态文案、解读和行动建议；作为数据负责人，我要求这项功能对旧业务库和报告文档库只有读取行为，不能以任何形式改变它们。

**Why this priority**: 可维护文案是页面可用性的前提；外部库只读是不可跨越的安全边界。

**Independent Test**: 在指标管理修改一个已登记的子指标文案并重新打开报告，验证文案更新；审查并测试所有新增的数据访问路径，确认只有 `nepstar` 命名空间可能出现写入，其他数据源全部只读。

**Acceptance Scenarios**:

1. **Given** 一个已登记的子指标，**When** 维护人员保存状态文案、指标解读或行动建议，**Then** 仅更新 `nepstar` 中该指标配置，重新打开详情可看到新文案。
2. **Given** 页面需要当前报告和历史得分，**When** 查询外部报告或历史信息，**Then** 只读取既有记录；不存在任何更新、插入、删除、建表、迁移或批量回填动作。
3. **Given** 外部数据源拒绝写入，**When** 正常使用本功能，**Then** 指标详情仍可读取并展示，不需要写权限。
4. **Given** 文案为空，**When** 保存或查看详情，**Then** 对应区域按空值规则隐藏，不向外部库写入默认内容。

### Edge Cases

- 报告源是三层树，V2 的“系统详情子指标”通常对应原始树的三级节点；不得因界面称其为二级详情而读取中间分类分数。
- 同名指标出现在不同系统时，以稳定业务编码及父子关系定位，不按名称模糊匹配。
- 历史报告在该指标登记之前产生，若其原始节点存在，仍可只读纳入趋势；若节点缺失则跳过。
- 历史记录的报告日期、分数或节点结构缺失时，忽略该点；当前报告无分数时，不展示虚假零分。
- 如果当前报告不是该客户的最新报告，趋势不得包含其后检测的“未来”报告。
- 外部数据源超时或不可用时不得回退到固定假数据；已有报告错误页应允许重试。
- 页面窄屏下不能出现左右外部露白、内容遮挡或横向滚动；卡片仍保留正常页面内边距。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 使用报告标识、客户标识和稳定指标编码定位单指标详情，并校验报告归属和就绪状态。
- **FR-002**: 系统 MUST 校验指标已启用、已登记真实报告标识、隶属于所请求系统且确实存在于当前报告；失败时不能回退到其他指标。
- **FR-003**: 指标详情 MUST 返回当前得分、原始异常等级、可用的状态文案、指标介绍、指标解读、行动建议及所属系统信息；缺失字段允许为空，不得用设计稿文案冒充真实结论。
- **FR-004**: 指标详情得分 MUST 与同报告系统详情中的对应指标一致，均取同一份原始报告，不在前端另算。
- **FR-005**: 趋势 MUST 只包含同一客户、同一原始指标标识、当前报告及其之前的最近至多六次有效检测，按时间升序排列；跳过缺失/无效记录，不补零。
- **FR-006**: 少于两次有效记录时，页面 MUST 展示首次有效记录提示而非折线；没有维护建议时 MUST 隐藏建议区域。
- **FR-007**: 指标管理 MUST 允许已登记的子指标维护状态、解读和行动建议，并继续应用现有输入校验与保存反馈。
- **FR-008**: 详情页 MUST 采用已确认的 V2 单指标高保真布局：全宽背景、紧凑导航、得分主卡、指标解读、真实趋势、行动建议、免责声明；加载时有对应骨架屏。
- **FR-009**: 详情页 MUST 不显示已明确移除的“本次表现”、底部返回大按钮、AI 长寿咨询入口及产品推荐卡；顶部返回控件保留。
- **FR-010**: 从系统详情进入和返回时 MUST 保留报告/客户/系统/指标上下文，并恢复系统详情进入时的阅读位置。
- **FR-011**: 本功能对 `platform`、`kj_fastplus`、MongoDB `receive_report` 及所有非 `nepstar` 数据源 MUST 严格只读；禁止 DDL、DML、迁移、同步、缓存回写和“修复数据”。这一限制高于功能便利性。
- **FR-012**: 本功能需要的可维护文案若发生写入，MUST 仅作用于 `nepstar` 现有业务配置；不得新增或修改其他库的结构或记录。
- **FR-013**: 详情接口 MUST 沿用现有错误边界：不存在/无权访问对外不可区分，未就绪与暂不可用分别可识别；请求不得泄露其他客户数据。
- **FR-014**: 页面 MUST 不使用模拟报告回退；出错时显示明确状态而不是白屏。

### Scope Boundaries *(mandatory)*

- **Canonical Target**: `nepstarAdmin/backend`、`nepstarAdmin/frontend` 和 `reportFront/report-v2`；文档位于 `specs/005-single-indicator-detail`。
- **Explicitly In Scope**: 单指标聚合读取、任意层级历史节点只读查找、子指标文案维护、报告 V2 指标详情和导航/骨架屏、相关测试。
- **Explicitly Out of Scope**: `reportFront/baogaoV2`、所有 V3、旧报告目录、`KH503`；产品推荐与 AI 入口；膳食/运动/营养三套新结构；真实报告数据迁移、回写或补录；任何非 `nepstar` 数据库的结构或记录变更。
- **Architecture Decision**: 沿用现有报告聚合服务及已建立的 MySQL/MongoDB 只读读取链路，不增加数据库表或新存储组件；对外部库施加只读权限属于部署安全要求，不能用应用代码代替。若实际权限不足或现有链路需要写入才能运行，停止并报告，不放宽红线。

### Key Entities

- **报告**: 受检客户的一次检测，拥有报告编号、客户归属、就绪状态和检测时间。
- **指标登记**: V2 展示编码、所属系统、原始指标标识及维护文案的映射配置。
- **单次指标结果**: 某份报告中的原始指标标识、得分、异常等级和可用的上次得分。
- **历史趋势点**: 同一客户同一指标在某次有效报告中的日期、报告编号和得分。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已登记指标的报告样本中，详情分数与其来源系统详情指标分数 100% 一致。
- **SC-002**: 一条有效记录时 100% 不显示虚构折线；至少两条时趋势不超过六点，按时间升序且全部可追溯到真实报告。
- **SC-003**: 从系统详情进入指标详情并返回，阅读位置误差不超过一个屏幕像素级滚动单位（允许浏览器原生四舍五入）。
- **SC-004**: 本功能新增数据访问路径对非 `nepstar` 数据源的写入、迁移和建表次数为 0，且使用只读凭据也能完成报告浏览。
- **SC-005**: 正常网络下 95% 的指标详情在 3 秒内完成内容或明确错误状态展示；加载期间始终有骨架屏。
- **SC-006**: 390–414 px 手机视口下无横向滚动、遮挡或页面两侧外部露白。

## Assumptions

- “二级指标详情”指 V2 系统详情页的子指标详情；该展示项在原始报告三层树中通常是三级节点，按已登记的原始标识精确读取。
- 当前确认的 UI 设计稿为本期页面范围；最后确认已去掉产品推荐和 AI 入口，未要求分类膳食/运动/营养建议。
- 只读外部库和文档库的网络连通性、只读账号授权由部署方提供；本功能不改这些数据源的账号、权限、配置和记录。
- 现有 `nepstar` 指标配置字段足以保存本期文案，不新增数据库表。
