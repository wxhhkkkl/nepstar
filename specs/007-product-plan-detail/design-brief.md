# 产品方案详情页设计简报

日期：2026-10-26。范围：当前报告端移动页面的健康管理方案详情。此文档为设计及后续规划依据，不是业务页面的实现代码。

## 设计目标

帮助查看者依次回答：这是什么方案、与本次报告有什么关联、包含什么产品、如何继续了解。

沿用现有浅蓝与白色表面、深蓝标题、蓝色主操作及真实产品照片。遵循用户最新反馈，优先舒适阅读，区块保持约 20–24px 间隔，不把全部内容压进首屏。

## 现有内容核对

来源为现有方案/商品维护结构及通过已有只读连接获取的已启用记录。没有修改记录或读取个人报告正文。

| 内容 | 已有来源 | 设计处理 |
| --- | --- | --- |
| 方案名称 | 健康方案名称 | 直接作主标题，无额外虚构营销标题 |
| 方案说明 | 方案 description | 展示于“方案简介”，自然换行 |
| 关联指标和分数 | 既有报告与方案匹配结果 | 中性关联提示，沿用报告分数语义 |
| 匹配条件 | 各方案 trigger_score_below | 后续读取沿用既有实际条件，不写死 80 |
| 产品名称和简介 | 关联商品及 description | 按关联顺序展示登记的整体商品 |
| 产品图片 | 封面及已维护图片列表 | 完整展示、保持比例，缺图不借用别的礼盒图 |
| 商品详细正文 | 已有 detail_html | 有内容时可展开；当前睡眠及钙流失礼盒正文为空 |
| 价格、订单、剂量、疗程 | 本期没有相应已确认能力 | 本期详情设计不展示、不补造 |

核对到的设计主样例：

- 方案：松果体睡眠健康管理方案。
- 方案说明：针对松果体分泌与睡眠节律的日常健康管理参考，帮助建立稳定作息并支持夜间恢复。
- 产品：松果体睡眠健康管理礼盒。
- 产品简介：围绕睡眠节律与夜间恢复设计的健康管理产品组合，仅作日常健康管理参考。
- 产品详细正文：空。
- 该方案当前维护的匹配阈值为 99；设计例子“性腺分泌 98”不能被解释成异常或诊断。
- 另有骨质疏松钙流失健康管理方案；同样存在礼盒简介但无详细正文，应使用相同空值规则。

## 页面内容顺序

1. 顶部返回及“方案详情”标题。
2. 方案首区：方案名称、产品主图及必要的方案说明。
3. 报告关联：本次指标、真实分数和查看指标入口。
4. 方案简介：后台维护的说明，不自动扩写成健康结论。
5. 包含的产品：真实商品名称、图片、简介及可用时的正文展开。
6. 底部左侧次操作“查看关联指标”、右侧主要操作“咨询 AI 长寿顾问”，附现有健康管理说明并预留安全区域。

用户已选定第三张，按上述阅读顺序呈现；后台内容与得分含义不随设计变化。

## 视觉方向与已确认基准

生成稿统一以 390×844 手机视口设计，不包含手机外壳或系统状态栏，使用同一真实产品照片。这里的方向名称用于生成管理；展示后的选择编号仅按聊天中图片实际出现的顺序确定。

- 报告关联优先：方案标题与小幅产品图并列，关联指标位于主要阅读位置，随后进入介绍和产品。
- 产品展示优先：较大产品图建立直观认知，标题与关联信息放在图片之后，正文使用简洁分隔。
- 清晰阅读与产品说明：轻量首区和较少装饰，突出方案介绍及产品说明的阅读顺序。

用户于 2026-10-26 明确选择第三张。最终基准为 `assets/design-03.png`，具体布局及交互记录见 [selected-design.md](selected-design.md)。本阶段为规格与设计确认，没有创建业务页面或新运行服务。

## 工程现状供后续规划参考

- 当前维护的报告应用位于 `reportFront/`，已有首页、系统详情、单指标详情及 AI 咨询；尚无方案详情路由。
- `reportFront/src/components/RecommendationCard.vue`：首页方案主操作目前进入系统详情，系统详情方案操作目前进入 AI 咨询。
- `reportFront/src/views/AiConsult.vue`：匹配方案列表的当前“查看方案”仍进入系统详情，列表已有默认单项和展开动画。
- `nepstarAdmin/backend/app/schemas/plan.py` 与商品维护结构已有所需名称、说明、关联、图片和详细正文能力。
- 当前报告展示中的产品简要输出仅含标识、名称和图像信息；后续需要在报告原有可查看边界内补齐只读详情，不把后台管理接口直接开放给报告查看者。
- 复用已有报告/方案/指标定位和外部只读约束，不在本阶段指定新的接口、模块或依赖。
