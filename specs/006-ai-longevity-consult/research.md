# Research: AI 长寿咨询实施决策

> 2026-10-12 当前实现修订：以下 R1/R7 的强制同意步骤属于早期决策，当前 Vue 页已取消该步骤，bootstrap 无告知/同意字段，会话同意引用可空（008）。不自动代用户同意，旧接口明确撤回仍生效。正式生产告知及处理依据仍待 T065 确认。下文外部资料是此前核对记录，本轮未重新联网验证，不作为当前服务商批准证明。

## R1. 公开报告与匿名聊天隔离

**Decision**：用户确认任何人均可通过报告链接查看报告，并可在明确同意后匿名咨询。报告号和客户号仅用于核对公开报告是否有效。匿名凭证仍使用至少 256 位随机秘密，HMAC 摘要存 `nepstar`，明文仅在当前标签页 `sessionStorage` 保存，最长 30 天有效，仅代表当前请求授权。每次进入 AI 咨询都新建空白会话，前端不保存会话 ID、不提供历史列表/读取/删除；完整问题和回答永久保存在 `nepstar`，没有自动清理或硬删除任务。该留存和不展示历史的规则并入用户实际确认的处理范围，使旧同意失效。

**Rationale**：现有 `report_view.py` 只验证 `report_code + customer_id` 与原始记录是否匹配，没有报告用户登录。公开报告定位参数不能作为聊天读取授权；匿名凭证只保护当前咨询请求，不证明访问者是报告本人。刷新可沿用 guest 授权凭证，但不会恢复以前的会话。永久留存与前台不可见需要在同意前清晰告知。[MDN：sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)

**Alternatives considered**：只凭公开 URL 查聊天会串人；将 URL 哈希成 token 仍让所有访问者共享同一秘密；复用管理端 JWT 要求报告访客登录，违背用户确认的业务流程。跨标签页或跨设备同步历史需要可核验身份，首版不提供。

## R2. 数据库写入位置

**Decision**：所有咨询新表、迁移和写事务只在 `nepstar`；新增专用 async engine/session，启动时解析并验证 `NEPSTAR_DATABASE_URL` 的数据库名和连接目标。用于读取 `platform`、`kj_fastplus` 与 MongoDB 的连接不在咨询代码路径执行 DML/DDL。

**Rationale**：现有 `database.py` 的通用 `get_db` 连接 `DATABASE_URL`，而 `NEPSTAR_DATABASE_URL` 当前主要提供表 schema；跨 schema ORM 访问不等于写连接受限。专用会话可在代码和权限层证明边界。

**Alternatives considered**：继续复用通用会话但手写 schema 前缀，仍可能把事务写到错误库；把会话存 MongoDB 与红线直接冲突。

## R3. 报告与历史证据

**Decision**：复用现有报告源读取，咨询专用历史查询增加“当前报告日期及以前”上界；只取同客户同 target_id 的有效记录，最多六次。报告证据带来源类型、报告号、检测日期、指标编码与可导航的路由。

**Rationale**：当前 `fetch_recent_indicator_trend` 明确会纳入当前报告之后的记录，适合最新趋势展示，却不符合旧报告咨询的时间语境。不能直接复用它的结果。

**Alternatives considered**：以当前趋势直接提问会发生“未来数据泄漏”；全部历史送模型浪费上下文并增加误引风险。

## R4. 模型与传输

**Decision**：首版在现有 FastAPI 进程内封装模型适配器，后端以 allowlist 控制取数能力；报告端以 `fetch` 消费逐步输出。候选服务商 DeepSeek 的 Chat Completions API 支持 SSE 流与 function tool calls；模型名、域名和凭据由服务端受保护配置提供，不写进前端。具体服务商启用以数据处理评估为前提。

**Rationale**：已有 Python 服务可做鉴权、取数、模型调用和 SSE，不需要新建常驻 Agent 服务。服务端代模型执行工具请求，并校验参数及来源。官方文档：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。

**Alternatives considered**：浏览器直连模型会暴露密钥和健康数据控制边界；单独新服务增加部署及鉴权复杂度；自由联网搜索不在首版需求内。

## R5. 管理权限与密钥

**Decision**：新增咨询菜单权限的显式路径/动作校验；配置发布与规则发布分别授权。模型密钥由服务端环境或密钥服务保管，后台只展示“已配置/未配置”和非敏感模型信息。发布事件只记操作人、时间、版本、变更摘要。

**Rationale**：现有 `check_permission` 实现只查用户是否拥有任一菜单的对应动作，没有把当前路由映射到具体菜单；直接复用不能保证 AI 配置发布权限。秘钥放在前端或可回显表单会扩大泄漏面。

**Alternatives considered**：把整个管理端都交给“已登录即可”会过宽；在 `sa_ai_consult_settings` 存可读明文密钥不合适。

## R6. 幂等、停用与留存

**Decision**：每轮问题有客户端幂等键及数据库唯一约束；每次模型生成有单独 generation id 和状态。完成轮次按匿名会话所在业务日计额度，并设全局成本与并发上限；失败尝试的模型用量仍记录。用户确认后台完整会话内容永久留存，不设会话内容到期或自动清理；30 天凭证期限仅阻断访问。报告端新进入时开启空白会话，不提供最近历史、完整会话读取或用户删除。

**Rationale**：断网重试与晚到流必须可靠区分，否则会重复记账或把本次答案串入新会话。完整留存由后台数据持久化保障，匿名用户不会借公开报告链接找回先前内容。

**Alternatives considered**：仅前端去重无法覆盖刷新和并发请求；只在数据库删行后取消模型请求存在晚到写回窗口。

## R7. 待确认的上线集成项

用户已确定公开链接匿名咨询及“当前标签页刷新可恢复，关闭后不提供找回”的产品选择。2026-10-08 用户明确批准：沿用现有 FastAPI 增加流式 AI 接口，只在 `nepstar` 新增匿名聊天相关表，并按阶段实施；真实模型调用先保持关闭。项目负责人于 2026-10-10 明确允许服务处理咨询所需报告健康信息，并要求补写单独用户须知；文案草案现见 [user-notice.md](user-notice.md)，尚未发布。用户告知/同意流程、匿名公开链接下报告主体授权路径、API 输入训练用途、留存/删除、数据区域和分包商等确认整理为独立放行门槛 T065，因此当前仍不向模型发送真实报告。2026-10-10 核查 DeepSeek 官方开放平台条款，面向公众的下游应用须事先披露个人信息处理规则并取得用户同意或其他合法依据；其消费者隐私政策不涵盖开放平台下游应用用户的数据处理，且消费者服务不面向健康等敏感个人信息。公开资料不是本项目适用的 API 数据处理协议。当前模型配置名 `deepseek-v4-flash` 被官方标为兼容旧名，现路由 V4.1-Flash；文档推荐名为 `deepseek-flash`。不在没有明确变更授权和适配测试前擅自更改配置。生产密钥来源、聊天存储加密和备份恢复策略也仍需独立验收；上述条件完成前只使用本地替身，真实服务保持关闭。
