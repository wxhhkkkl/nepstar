# AI 长寿咨询：直接运行 FastAPI 的部署检查与回退

更新：2026-10-12。适用于用户当前的云服务器/Python 虚拟环境部署，不要求 Docker、Kubernetes 或迁移到 systemd。本文是执行前检查说明，**不表示已部署、已迁移或已批准真实健康数据外发**。

## 当前规则优先

- 公开报告由 `reportId/userId` 定位；聊天记录必须绑定报告及报告客户号，不创建独立 guest 登录账号。代码中的 guest 是保护本次聊天的随机凭证记录，不证明访问者是报告本人。
- 每次进入/刷新咨询页开始空白，不显示最近或以前的咨询。单轮状态核对仅用于本页面的新会话，不能找回旧咨询。
- `nepstar` 永久保存完整问题、回答及必要关联信息，不按 30 天删除；30 天仅是访问凭证有效期。不得安装或保留旧的 retention/purge 清理任务，凭证到期不能触发正文删除。
- 所有咨询写入和迁移只允许在 `nepstar`；其他 MySQL/Mongo 数据源必须只读。备份不能成为通过其他库写入来绕开该红线的理由。
- 当前主应用已有每分钟检查积压 generation 的恢复循环，`AI_CONSULT_OPERATIONS_READY` 未显式禁用且专用写连接配置通过时运行。它结束超过三分钟仍在运行的失败尝试，不删除已完成咨询/会话/原问题，不是保留期清理；不要为它重复增加 cron。

### 后台开关与部署环境（本次修复）

数据库 `nepstar.sa_ai_consult_settings.enabled` 是服务总开关，默认 false；后台顶部开关通过独立 `/ai-consult/admin/service-state` 启停，不需要重启进程。四个旧环境变量未配置时委托后台控制；显式 `false` 保留为部署硬禁用，`true` 只表示允许后台开启。环境禁用时页面会显示具体原因，不能绕过。

上线交付需同时更新管理端、报告端（暂停提示）和当前报告链接实际使用的后端。报告端若请求线上域名，操作本地 127.0.0.1 后台不会改变线上状态。先完成发布门槛，由部署负责人在目标环境删除旧的四个强制 false 配置或改为 true，并按实际运行方式重启全部 worker，让环境变化生效；再登录同环境后台手动开启。此步骤不是本次自动操作的授权，本次未改 `.env`、数据库开关或线上服务。

紧急暂停优先使用后台开关：新请求/重试被拒绝，尚未完成发布检查的回答保存失败终态并保留用量，不删除历史。关闭再恢复不会复活暂停前生成。后台不可用时，部署负责人仍可将环境设为 false 并重启全部 worker。设置页保存额度不改变启停状态。

## 1. 确认运行的确实是本项目

仓库提供 `nepstarAdmin/backend/deploy.sh` 用于 Linux 直接运行服务的日常更新，使用方法见 `nepstarAdmin/backend/DEPLOY.md`。它在停止旧进程前安装独立环境依赖、检查配置及只读表结构，确认当前目录的单进程 uvicorn 后平滑重启并检查健康状态；不会执行迁移、修改开关或清理记录。`start-dev.sh` 仍为开发脚本。截图中自动执行 Alembic 的旧部署脚本未提供，不能与新脚本混用。截图的服务标题与本仓库名称也不能作为同一项目的证明。

服务器操作前核对实际工作目录、Python 虚拟环境、`app.main:app` 的来源、上传版本和 `.env` 文件位置。本项目健康检查是 `GET /api/v1/health`，返回 `{"status":"ok"}`；它只证明应用活性，**不检查 MySQL、Mongo、AI、表版本、权限或积压**。

不要为了确认服务而运行有自动迁移、安装或重启行为的未知脚本，不要以猜测 PID 的方式停止进程。实际部署脚本需去除密码/密钥后审阅；本轮没有连接云服务器或重启任何服务。

## 2. 离线配置检查（可先执行，无数据库/模型连接）

在服务器**实际 backend 目录**，使用与应用相同的虚拟环境和环境注入方式执行：

```sh
.venv/bin/python scripts/ai_consult_preflight.py --env-file .env
.venv/bin/python scripts/ai_consult_preflight.py --env-file .env --prepare-pilot
```

如果服务器虚拟环境名称是 `venv`，只需替换 Python 可执行路径；不能据本机名称修改线上环境。

- 普通模式检查关闭状态；允许尚未配置聊天密钥/专用连接时给出 warning，但不能将其视为 AI 可用。
- `--prepare-pilot` 要求完整 `nepstar` 写连接、聊天凭证摘要密钥、服务端提供方/模型/密钥、HTTPS 精确主机白名单及有限超时；**仍要求四个公开开关关闭**。
- `NEPSTAR_DATABASE_URL` 必须显式使用 `mysql+aiomysql` 驱动和精确库名 `nepstar`。检查器保守拒绝 query 参数，防止覆盖连接目标；不回退到 `DATABASE_URL` 或其他库。
- 环境变量优先于 `.env`，键名不区分大小写；文件缺失、格式错误或同来源大小写冲突会拒绝，不会默默按默认关闭通过。
- 程序不 import `app`，不创建数据库 engine，不连接任何数据库、AI 或网络，不执行迁移，不启动服务，不修改文件/配置。
- 输出只有固定检查名/状态/说明，不打印连接串、主机、客户信息、问题、回答或密钥；不要把 `.env` 原文上传到聊天或日志。
- 退出码 0 仅表示离线检查通过，退出码 2 表示有阻挡或无法读取配置；`ready_to_enable` **始终为 false**。人工门槛不可能由配置字符串证明。

先以关闭状态部署候选代码，再完成以下验证。不要添加自动“检查通过就启用 AI”的部署步骤。

## 3. 数据库与备份门槛

1. 由 DBA/部署负责人核对专用写连接的真实默认库是 `nepstar`，并核对报告 MySQL/Mongo 账号权限为只读。字符串指向正确库不证明权限正确或能连通；应保留去身份化权限与命令计数证据。
2. 审查当前 Alembic 版本与迁移链：`006` 依赖 `005`，`007` 依赖 `006`，`008` 依赖 `007`。008 仅把 `nepstar.sa_ai_consult_session.consent_id` 改为可空，保留已有选择及引用；有空引用时拒绝降级，不能删会话后强行降级。已有库版本不能靠猜测或 `stamp` 跳过核验；不得在生产运行会创建/删除测试表的隔离测试。
3. 仓库默认 `alembic.ini` 连接不是 `nepstar`，`env.py` 也不会自动把它换成 `NEPSTAR_DATABASE_URL`。**不得直接执行默认配置的 `alembic upgrade head`**，不得把带密码的 URL 放进命令参数。需要经审阅的专用 runner/配置，连接及版本表目标均限定 `nepstar`；审查整条迁移链，而不只看 006/007/008 的保护。本轮没有执行迁移。
4. 迁移前备份 `nepstar` 并在隔离的、明确授权的 `nepstar` 恢复目标演练；核对问题、回答、报告/客户绑定、规则、审计和用量能够恢复。咨询业务记录永久保存，不安装任何按凭证过期删除记录的作业。备份轮换/灾备细则单独审批，本轮不设自动到期或删除。
5. 本轮不提供可直接执行的生产迁移命令，也不运行迁移、grant、回填、菜单初始化或清理。上线前还需审查应用启动的种子数据逻辑，确保所有写入只触达 `nepstar`。

## 4. 服务商、后台与代理门槛

| 主题 | 必须核验的证据 |
| --- | --- |
| 服务商 | 实际提供方/模型、健康数据处理和留存条件、访问者同意、密钥托管及批准记录；不得仅凭用户说“下一步”外发真实报告 |
| 后台设置 | provider/model 与服务器一致；正式告知/授权方案验收；规则有审计；入口、日额度、总体预算和并发适合试点；额度保存不改变服务状态，独立开关须人工确认 |
| 权限 | 实际 JWT 账号/角色/菜单逐动作测试；公开报告凭证不具有管理员权限；撤权后旧 JWT 被拒绝；其他标签页与旧会话内容不可读 |
| 数据 | 当前报告数值、日期、系统与来源引用对得上；方案 79/80/81 分和下架边界通过；其他库 DML/DDL/回写为零 |
| 流与网络 | 反向代理对咨询 SSE 不缓存、不缓冲，空闲超时覆盖客户端 65 秒等待窗口，响应开始和完成都能及时到手机；ASGI 计时不能证明代理行为 |
| 日志 | 代理、Uvicorn、异常追踪与采集链均不记录 Authorization、正文、完整报告/用户参数或未脱敏错误。检查响应体与日志，不开启包含聊天正文的 debug 日志 |
| 运行恢复 | 实际进程中恢复循环确实运行；后台 `/ai-consult/admin/operations` 的积压、失败和用量可核对。零积压不证明循环健康；恢复失败、持续超三分钟积压需告警 |

不得把后台设置接口或一般健康检查当作上述内容的自动证明；没有证据时保留“未验收”。

## 5. 分阶段试点，不直接全量开启

1. 默认关闭部署：四个 `AI_CONSULT_*` 入口/会话/回答/运营开关保持 false，后台 settings 的 enabled 保持 false。先核对非 AI 管理/报告功能没有回归。
2. 在专用隔离环境上进行 MySQL 锁/幂等与只读全链路验收，不使用生产库作为可销毁测试库。现有真实 MySQL 测试会创建和移除 AI 表，仅适用于明确确认为空的本机 `nepstar` 隔离实例。
3. 完成服务商批准、告知、数据/授权/安全硬门槛、部署脚本审查和人工放行后，在限定试点环境解除部署硬禁用，由有设置页编辑权限的管理员确认开启总开关。后端重新校验密钥摘要、模型匹配、维护与非零额度，不直接运行绕过接口的启用 SQL。
4. 收集 SC-001～SC-010 的实测记录。用户体验与反馈指标在试点期间测量，不因“必须先有反馈”而跳过前面的安全门槛，也不能在首批 50 个反馈尚未完成时宣称全量验收通过。
5. 门槛未通过就保持关闭；本地 mock 与静态设计图不能替代真实模型、反向代理、MySQL 或手机测试。

## 6. 回退（保留所有咨询数据）

由线上部署负责人执行，而不是本轮自动执行：

1. 优先使用后台开关关闭咨询（无需重启）。若后台不可用，将四个公开/运营开关设为 false，并按已经核验的实际部署方式平滑重启所有 worker，确认无旧进程继续接受提问。环境更改需要重启，后台总开关不需要。
2. 使用不带真实健康正文的验收请求核对 guest 创建/提问被拒绝，管理与报告基础功能仍可用。不能只看配置文件，因为运行进程可能仍使用旧环境。
3. 保留 `nepstar.sa_ai_consult_*` 的完整问题、回答和关联记录，不执行 `alembic downgrade`、DROP/TRUNCATE、retention/purge 或历史清理。数据库备份同样不在本次回退中删除。
4. 对尚未完成的尝试，仅按已有状态恢复逻辑结束/隔离；不要删除原问题、已完成回答或后继 generation。重启/停止不保证模型服务商立即停止计费或退款。
5. 如需回退代码，确认旧版不会启动已废弃的清理作业；优先关闭功能而不是回到带 retention/purge 的旧版本。必要时撤销服务商凭据；本次未修改任何凭据。

## 验收记录最小格式

记录代码版本、测试环境、是否为合成数据、测试时刻、负责人、样本/并发数、P50/P95/P99、失败数、SQL/Mongo 写命令计数、代理与真机证据、服务商及人工审批状态。记录中不得包含密钥、完整报告、客户姓名或聊天正文。待填项必须明确“未验收”，不能空白默认通过。
