# Specification Quality Checklist: 基于个人报告的 AI 长寿咨询

**Purpose**: 在实施规划前检查需求的完整性、边界和可验收性。

**Created**: 2026-10-08

**Feature**: [spec.md](../spec.md)
**Product Design**: [product-design.md](../product-design.md)

## Content Quality

- [x] 需求不规定框架、模型调用协议或表结构；仅保留用户指定的候选服务与既有目录/数据边界。
- [x] 围绕看懂报告、连续提问与行动建议描述用户价值。
- [x] 面向业务人员表述，技术现状与候选能力说明分离到设计稿。
- [x] 包含所有必需章节，保持模板章节顺序。

## Requirement Completeness

- [x] 无未解决的需求澄清标记；可合理默认的策略均写入 Assumptions。
- [x] 功能要求可测试，31 条要求均对应具体用户故事。
- [x] 成功标准可测量，覆盖时间、样本数量、准确性与泄露/写入次数。
- [x] 成功标准采用用户可见结果与业务边界，不绑定技术实现。
- [x] 六个用户故事分别包含独立验证方式及验收场景。
- [x] 覆盖缺失报告、guest 凭证失效、错误分数、历史不足、中断、重复、跨报告及不当指令等边界。
- [x] 明确本期只进行设计，列明首版范围和排除项。
- [x] 标明匿名聊天隔离、服务商条件、内容审核、试点额度和保留策略等依赖与假设。

## Feature Readiness

- [x] 入口、依据回答、追问行动、会话恢复、方案规则及运营能力均有验收条件。
- [x] 主路径覆盖首次进入、匿名凭证、访客同意、提问、追问、回看依据、返回报告与当前标签页恢复。
- [x] 成功指标覆盖主要价值和不可越过的数据只读边界。
- [x] 需求中未写入未验证的模型准确率、临床疗效或已实现能力。

## Notes

- 本次为文档质量检查，不表示运行代码、模型回答或生产部署已通过测试。
- 用户确认报告链接公开，任何访问者均可在同意后匿名咨询；报告参数不构成聊天凭证。当前标签页刷新可恢复聊天，关闭标签页后仅凭公开链接不找回。
- `reportFront/` 为用户后来指定并且当前实际存在的报告端目录；旧规范中的嵌套路径不用于本期。
- 模型通信与 `nepstar` 新表的架构已获用户确认；服务商健康数据处理条件与专业内容审核仍属于上线前依赖。不再要求不存在的已登录报告入口。
- 30 天保留、每日 20 次问答与并发 20 人是建议的试点假设，未被表述为用户已批准的生产策略。
- 需求、规划和任务已同步公开链接匿名咨询的产品选择；后续按 `tasks.md` 实施。
