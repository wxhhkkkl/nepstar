# Contract: 管理后台 AI 咨询 API 与页面

路径 `/api/v1/ai-consult/admin`。沿用现有管理端登录 JWT，但每个接口须按 `/health/ai-consult-settings` 或 `/health/ai-consult-overview` 的**具体菜单与动作**校验权限；规则草稿创建需要设置页 `edit`，发布和回退需要设置页 `publish`，不能沿用“拥有任一菜单动作即可”的通用判定。响应沿用 `{code,message,data}`，错误同时给正确 HTTP 状态。

权限映射以框架已经匹配的路由模板和 HTTP 方法为准，兼容完整 `/api/v1/ai-consult/admin/...` 与原始 `/ai-consult/admin/...` 模板；不使用请求参数或原始 URL 推断授权。未知模板/方法在管理员绕过前拒绝。角色停用、菜单停用及权限撤销在下次请求立即生效；`/auth/me` 的动作去空格、忽略空项并去重，与后端精确动作匹配一致，`preview`/`republish` 等子串不能充当 `view`/`publish`。公开报告的访问凭证不替代管理端登录 JWT。

## 管理页面

| 页面 | 首屏信息 | 可操作项 | 权限 |
| --- | --- | --- | --- |
| `/health/ai-consult-settings` AI 咨询配置 | 服务状态、服务商/模型、密钥是否已配置、每匿名会话额度、全局每日 token/并发上限、告知版本、当前规则版本 | 开关、额度与维护文案；保存草稿、发布/回退规则 | 查看/编辑/发布分别授权 |
| `/health/ai-consult-overview` 运行概览 | 新会话、完成率、当日/当月实际 token；小时/自然日趋势；报告与用户绑定的会话列表 | 日期/月切换；报告编号、用户 ID、建立日期、状态筛选及分页；对话详情抽屉 | 汇总及元数据为 `view`；完整问答另需 `conversation` |

布局沿用管理端现有浅色 Element Plus 样式。配置页先显示服务状态与最近发布信息，再显示基础配置和规则版本。2026-10-10 按用户新要求，概览从仅汇总扩展为后台会话检索与问答详情；移除提问轮次、生成尝试、首次可展示回答三张统计卡，不新增实名、手机号查询或批量导出/删除。普通概览查看权限不自动获得正文权限；角色编辑页须显式勾选“查看会话完整对话（含健康信息）”，系统管理员可直接查看。报告端仍不提供历史功能。

## API

| 方法与路径 | 行为 |
| --- | --- |
| `GET /settings` | 返回非敏感配置、`credential_state: configured/missing`、当前规则及 `row_version`，不返回密钥 |
| `PUT /settings` | 保存额度、模型标识和维护文案，`enabled` 必须保持当前状态；不能通过保存设置启停服务。配置锁及 `expected_row_version` 防覆盖，冲突 409，写审计 |
| `PUT /service-state` | 设置页 `edit` 权限；严格 JSON `{enabled: boolean, expected_row_version: integer}`。独立启停接口，关闭不依赖模型/部署门槛，开启须通过运行配置检查；只修改 `nepstar` 的总开关/版本/更新时间及追加审计，不清理或删除问答；相同当前状态不重复写审计 |
| `GET /rules` | 分页返回版本、状态、作者与时间，不返回正文 |
| `GET /rules/{id}` | 有设置页查看权限时返回该版本正文，并校验内容摘要 |
| `POST /rules` | 有设置页编辑权限时创建不可原地修改的草稿；版本唯一，拒绝报告编号/手机号/邮箱等私人数据 |
| `POST /rules/{id}/publish` | 需要独立 `publish` 动作；只发布完整性校验通过的草稿，锁定 settings 行、校验 `row_version`、更新指针并写审计 |
| `POST /rules/{id}/activate` | 需要独立 `publish` 动作；回退到完整性校验通过的既有已发布版本，不覆盖旧正文并写审计 |
| `GET /operations` | 兼容旧 UTC 当日汇总接口；新概览不再使用其实际/预留合并占用作为消耗 |
| `GET /dashboard?day=YYYY-MM-DD&month=YYYY-MM` | 概览 `view`；北京时间所选日新会话、已结束尝试完成率、运行/超时积压、所选日/月 token 汇总与 24 小时/整月自然日趋势；缺省当日/当月，禁止未来日期/月 |
| `GET /sessions?report_code=...&customer_id=...&start_date=...&end_date=...&state=...&page=1&page_size=20` | 概览 `view`；报告精确匹配、正整数用户 ID、北京时间建立日期闭区间、`empty/active/ended`（未提问/进行中/已结束）筛选；总数、分页及活动时间倒序；不查询或返回问题/回答/凭证 |
| `GET /sessions/{session_id}?limit=30&offset=0` | 概览独立 `conversation` 权限；UUID 会话标识；按轮次顺序返回永久保存的完整问题、完整最终回答、状态、反馈、纯文本依据标签及安全的生成/token 元数据；分批加载且不截断正文；不存在为 404 |
| `GET /audit?limit=20&offset=0` | 设置页查看权限；只读 `nepstar` 内配置/规则操作，返回分页和白名单摘要，不回传原始审计 JSON、健康会话正文或系统清理记录 |

服务凭据仅由部署环境或密钥服务注入；后台不得回显、下载或通过 JSON 响应传递。若未来要在页面轮换密钥，需要另立需求和权限设计。规则内容只作为受限的表达风格参考传给模型，不能覆盖系统事实、安全约束；新轮次在创建时固定规则版本，重试复用该版本。规则版本在 `nepstar` 中不可变并由摘要校验。

会话生命周期（2026-10-12）：没有问题的记录显示“未提问”；已提问且未离页、距最后发送或重试不足 10 分钟显示“进行中”；离页结束接口已提交，或距最后发送/重试达到 10 分钟则显示“已结束”。服务端查询和公开访问均校验时间，浏览器关闭导致结束信号丢失时仍会到期结束。单轮回答成功、失败或审核未通过只影响轮次详情及“回答成功率”，不决定会话生命周期。使用已有 session.status/last_activity_at 字段，无新增表或迁移。

### 紧急启停（2026-10-12）

- 设置页顶部显示独立开关、服务实际可用状态及具体阻断原因。操作须确认，等待/失败时不乐观改变状态；冲突或网络失败后重新读取实际状态，不覆盖未保存的额度草稿。仅查看角色不能启停。
- 数据库总开关 `enabled` 默认 false。四个旧环境开关未设置时由后台接管；显式 false 是部署硬禁用，true 仅允许后台开启，不自动启动咨询。密钥摘要、提供方/模型、非零入口/额度/预算/并发和维护状态仍校验；不再硬编码“功能尚未完成”。
- 暂停动作追加 `service.pause` 审计，恢复追加 `service.resume`，与状态版本同事务提交。状态读取/切换响应不缓存。既有审计主键作为暂停栅栏，不新增表或迁移；生成在准入、准备前和最终发布检查中核对，暂停后很快恢复也不能放出关闭前未完成的回答。
- 旧请求被拦截时，保存 `failed/service_paused`，不保存/发送正文和依据；真实 token 已知则保留，未知仍按预留处理。已经发往服务商的请求不能保证马上取消或退款；已完成回答和后台完整历史不删除。
- 页面只控制当前管理端连接的 API。本地后台不是线上开关；报告端使用 `https://nepstar.kangjia.online` 时，应部署新后端并从连接该环境的管理端操作。环境阻断需由部署负责人处理，不能在后台覆盖显式 false。

### Token 统计与会话详情边界

- 数据仅来自显式 `nepstar.sa_ai_consult_*`；无新增表、迁移、模型请求或其他库访问。新读取接口不进行数据修复/回填；唯一写操作为已有 `nepstar` 审计表的正文访问审计。
- `input_tokens/output_tokens/actual_tokens` 只累计模型已同时回传输入和输出 token 的 generation，包括失败尝试已确认的用量与重试。缺失任一用量时不推测实际消耗，`budget_tokens` 单独计入 `reserved_tokens`，并返回 `unreported_attempts`。
- 按 `started_at` 归属时间；数据库为 UTC，边界及分桶统一 UTC+8，不依赖 MySQL 时区表。历史无数据时段为零，未来时段为 `null`；无已结束样本时完成率为 `null`，不伪造 100%。不是人民币费用或服务商账单。
- 会话详情不因旧访客凭证过期或会话旧 `deleted_at` 标记而清除/隐藏；服务端继续永久保存。本接口不赋予访问者恢复历史的能力。
- 对话内容用纯文本插值显示，保留换行，不执行 HTML/Markdown 中的脚本。只返回依据名称，不返回任意原始 JSON、携凭证 URL、token 摘要、provider request ID、未审核流式片段。
- 每次成功读取正文前，先提交 `session.read` 审计（管理员 ID、会话 ID、分页范围、时间）；审计提交失败返回 503 且不交付正文。配置审计列表显示配置、启停及规则动作，不混入聊天内容。
- 三个新接口响应带 `Cache-Control: no-store`、`Pragma: no-cache`、`Vary: Authorization`。普通查看角色直接请求正文收到 403，权限在每次请求重新核验。

## 验证边界

额度字段只接受 JSON 整数，不将布尔、数字字符串、空值或小数转换为额度；越界返回 422。管理端清空输入不能以缺省 0 提交，字段错误应贴近输入框显示，失败时保留草稿。限制分别为：入口创建与每日成功回答 0–1000、每分钟提问 0–60、全站每日 token 0–100000000、并发 0–100、单次提问 `max_question_chars` 1–500（缺省 500）。最后一项使用已有配置字段，不需数据库迁移；bootstrap 返回该上限，报告端同步输入与发送前校验，服务端生成准入再次校验。更改字数上限纳入配置审计，但不保存问题正文到配置审计。

- 未授权用户对配置发布、规则发布和运行数据分别收到 403；普通已登录管理员不自动获得发布权限。
- 关闭服务后新问答返回 `consult.disabled`，已完成聊天仍可凭当前 guest 凭证阅读。
- 用量统计按真实 generation 尝试累计；每匿名会话额度按 completed turn 计，不能因重试重复扣减。重新开标签页可以获得新 guest，因此还需全局成本/并发保护。
- 发布规则、改变服务商或告知范围时，按新版本判断是否需要重新征得当前匿名访问者同意。
