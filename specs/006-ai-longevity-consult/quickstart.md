# Quickstart: AI 长寿咨询开发与验收

这是实施指南；当前仓库仍只有需求和 UI 原型，以下接口、表与真实 AI 问答尚未实现。不要把 [静态交互预览](ui/README.md)当作联调环境。

## 1. 先确认集成边界

1. 取得可信报告用户入口的签名声明契约：签发者、主体、报告范围、一次性 nonce、过期及撤销；不能从裸报告 URL 自行签发。
2. 确认模型服务商、健康数据处理条件、告知文案与密钥托管；没有完成时保持服务关闭，只用本地替身数据开发。
3. 确认 `NEPSTAR_DATABASE_URL` 明确指向 `nepstar`；报告读连接、MongoDB 与旧库只用只读账号。审阅 Alembic 生成 SQL，确保只有 `nepstar.sa_ai_consult_*`。
4. 确认新增表和流式通信的架构变更已获批准，然后进入 `/speckit-tasks` 细化工作项。

## 2. 按测试先行实施

每一条工作项先写会失败的用例并运行确认，再实现使其通过。建议顺序：

1. 授权：裸 `reportId/userId`、伪造/过期/跨报告凭证失败；有效凭证只读核对后成功。
2. 数据：旧报告历史截止当天；缺项/冲突不编造；79/80/81 分与方案下架边界。
3. 状态：同一幂等键只创建一轮；停止、删除和重试后旧 generation 不得写回；失败不扣成功额度。
4. 回答：未知证据 ID、错误数值/日期、危险医疗内容不作为完成答复；用户自述与检测事实分开。
5. 页面：欢迎、加载、同意、生成、断网、额度不足、空历史、失效入口；软键盘与返回阅读位置。
6. 管理：每个动作按具体菜单授权；密钥绝不回显；规则发布可追溯；概览无私聊正文。

## 3. 本地运行（实施完成后）

在 `nepstarAdmin/backend/` 以隔离的本地 `nepstar` 测试库运行 `pytest`；模型调用通过本地 fake adapter，外部 MySQL 与 MongoDB 用只读替身。后台的依赖与测试配置见 `pyproject.toml`。报告端在 `reportFront/` 执行 `npm test` / `npm run build`，管理端在 `nepstarAdmin/frontend/` 执行 `npm test` / `npm run build`。

本地假签发者仅用于测试，不能作为生产授权入口；开发测试不得向候选 AI 厂商发送真实报告、问题或姓名。真实服务联调需独立的授权入口与专门的试点数据/同意。

## 4. 最终验收矩阵

| 验收主题 | 最低证据 |
| --- | --- |
| 数据准确 | 至少 40 个含缺失、冲突、历史边界的报告问题；引用值、日期、所属报告 100% 对得上 |
| 隐私授权 | 至少 20 个跨人、过期、分享链接用例；私人会话泄露 0，未同意外发 0 |
| 交互恢复 | 停止、重试、刷新、切报告与删除后无重复消息、重复扣额或晚到答案 |
| 移动端 | 320/360/375/390/414/430 px；iOS 与 Android 真机软键盘、底部安全区和点击目标 |
| 健康边界 | 至少 20 个急症、诊断、处方与延寿承诺样本；通过专业审核 |
| 管理能力 | 非授权管理员不能发布；关闭开关生效；用量和失败统计与生成尝试一致 |
| 库隔离 | 只有 `nepstar` 发生咨询 DML/DDL；外部只读账号下完整问答仍可运行 |

最终上线门槛与目标数值以 [spec.md](spec.md) 的 SC-001～SC-010 为准。所有目标都要以真实验证结果报告，不能以设计稿或单元测试替代实测结论。
