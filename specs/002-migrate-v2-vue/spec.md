# Feature Specification: V2 报告前端框架迁移

**Feature Branch**: `002-migrate-v2-vue`  
**Created**: 2026-09-15  
**Status**: Draft  
**Input**: User description: "将 reportFront/report-v2 从原生 HTML、CSS、JavaScript 迁移为 Vue 3 + JavaScript 项目。保持首页、二级详情页、68 分警示、系统排序、产品推荐、AI 咨询入口、响应式布局及保存长图功能一致。本阶段继续使用现有模拟数据，不接入后台 API，不修改 V3、baogaoV2、旧版报告和 KH503。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看完整长寿指数报告 (Priority: P1)

作为报告查看者，我希望打开 V2 报告首页后看到与迁移前一致的总分、年龄对比、系统指标、风险提示和视觉布局，以便继续理解自己的健康状态，不需要适应新的页面结构。

**Why this priority**: 首页是报告的主要入口，内容、顺序或视觉状态发生偏差会直接影响报告解读。

**Independent Test**: 使用同一组模拟数据分别打开迁移前后的首页，在约定的手机、平板和桌面宽度下逐项核对内容、顺序、警示状态、产品图和交互入口。

**Acceptance Scenarios**:

1. **Given** 当前报告模拟总分为 68，**When** 用户打开首页，**Then** 页面显示 68 分并呈现低于 70 分的警示状态。
2. **Given** 内分泌和骨骼是低分且有关联方案的系统，**When** 用户浏览系统区域，**Then** 两项低分系统及各自推荐方案优先于其他系统展示。
3. **Given** 报告包含七个当前用户适用的身体系统，**When** 用户向下浏览完整页面，**Then** 所有系统卡片、图表、文字和底部声明均完整显示且没有异常空白。
4. **Given** 用户启用了减少动态效果，**When** 首页载入，**Then** 所有内容直接显示最终状态且不因入场动画保持隐藏。

---

### User Story 2 - 查看系统详情并返回原位置 (Priority: P1)

作为报告查看者，我希望点击任一身体系统后进入对应详情页，看到与首页分数和图表一致的详细信息，并能返回首页原来的浏览位置。

**Why this priority**: 首页与详情页的数据一致性是用户信任报告内容的基础，也是现有 V2 的核心流程。

**Independent Test**: 依次从首页进入七个系统详情，核对系统名称、分数、图表、指标与建议，然后返回首页验证滚动位置。

**Acceptance Scenarios**:

1. **Given** 用户位于任一系统卡片，**When** 点击该卡片，**Then** 打开对应系统详情并展示相同的系统名称、分数和指标数据。
2. **Given** 内分泌或骨骼存在产品推荐，**When** 用户进入对应详情，**Then** 详情页在问题内容下方展示匹配的推荐方案和完整产品图。
3. **Given** 其他系统没有产品推荐，**When** 用户进入对应详情，**Then** 页面不展示无关或占位推荐卡片。
4. **Given** 用户从详情页返回首页，**When** 首页恢复，**Then** 页面回到进入详情前的浏览位置。

---

### User Story 3 - 使用报告辅助入口 (Priority: P2)

作为报告查看者，我希望继续使用 AI 长寿咨询入口和保存报告功能，以便查看咨询设计内容或保存完整报告长图。

**Why this priority**: 这两项是现有 V2 已确认的辅助功能，迁移后必须保持可用，但不阻塞核心报告阅读。

**Independent Test**: 在首页不同滚动位置验证 AI 入口可见并可打开目标内容，点击保存按钮验证下载行为和反馈状态。

**Acceptance Scenarios**:

1. **Given** 用户浏览首页任意位置，**When** 查看页面右下区域，**Then** AI 长寿咨询悬浮入口保持可见且不遮挡关键内容。
2. **Given** 用户点击 AI 长寿咨询入口，**When** 目标打开，**Then** 展示当前 V2 已有的 AI 长寿咨询设计内容，本阶段不发起真实对话请求。
3. **Given** 用户点击保存报告，**When** 浏览器支持文件下载，**Then** 下载当前 V2 报告长图并显示保存反馈。

### Edge Cases

- 详情地址包含未知系统标识时，页面必须提供可理解的回退提示和返回首页入口，不能显示空白页。
- 产品图片、医生头像或长图资源加载失败时，布局必须保持稳定，并显示替代文本或可识别的回退状态。
- 页面在 320 像素窄屏、常见手机宽度、平板及桌面宽度下不得产生横向滚动。
- 用户快速重复点击系统卡片、返回按钮或保存按钮时，不得产生重复页面、错误状态或持续反馈动画。
- 用户直接打开详情地址、没有首页滚动记录时，返回操作必须仍能回到报告首页。
- 动画尚未播放完成就开始滚动或保存时，报告内容不得缺失。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 保留当前 V2 首页的全部业务信息、视觉层级、资源和交互入口。
- **FR-002**: 系统 MUST 使用当前模拟数据展示总分 68，并在总分低于 70 时呈现明确警示状态。
- **FR-003**: 系统 MUST 优先展示低分且有关联推荐的内分泌和骨骼系统，并将各自推荐紧邻对应问题展示。
- **FR-004**: 内分泌推荐 MUST 显示针对松果体的“睡眠健康管理方案”及完整睡眠产品图。
- **FR-005**: 骨骼推荐 MUST 显示针对骨质疏松的“钙流失健康管理方案”及完整钙流失产品图。
- **FR-006**: 系统 MUST 保留七个当前用户适用的系统模块及其现有图表、指标、说明和展示顺序。
- **FR-007**: 每个系统卡片 MUST 可进入对应详情，详情数据 MUST 与首页相同系统的数据一致。
- **FR-008**: 详情页 MUST 仅在当前系统存在推荐时展示对应方案，推荐 MUST 位于对应问题内容下方。
- **FR-009**: 系统 MUST 在用户从详情页返回时恢复首页进入详情前的滚动位置；没有历史位置时回到首页默认位置。
- **FR-010**: AI 长寿咨询入口 MUST 在首页滚动过程中保持可访问，并继续打开当前静态咨询设计内容。
- **FR-011**: 保存报告功能 MUST 继续下载当前 V2 首页长图，并提供明确的点击反馈。
- **FR-012**: 页面 MUST 支持现有响应式范围，在窄屏、常见手机、平板和桌面视口中保持内容完整且无横向溢出。
- **FR-013**: 页面 MUST 尊重用户的减少动态效果设置，并确保关闭动画后所有信息直接可见。
- **FR-014**: 本阶段所有报告内容 MUST 来自项目内模拟数据，不得请求管理后台或其他远程业务接口。
- **FR-015**: 本阶段 MUST 复用当前 V2 已有图片和视觉资源，不得改变已确认的产品形象与报告内容。
- **FR-016**: 系统 MUST 为未知详情标识、资源加载失败和下载不可用提供不会破坏主流程的回退状态。
- **FR-017**: 系统 MUST 使用 Vue Router 统一管理报告首页与系统详情页导航，并将旧的 `detail.html?id=<systemId>` 地址兼容跳转到对应的新路由。

### Scope Boundaries *(mandatory)*

- **Canonical Target**: `reportFront/report-v2`
- **Explicitly In Scope**: V2 首页、通用系统详情页、模拟数据、68 分警示、系统优先排序、两项产品推荐、AI 咨询静态入口、响应式布局、滚动位置恢复、报告长图下载和现有视觉资源。
- **Explicitly Out of Scope**: `reportFront/baogaoV2`、全部 V3 目录、`reportFront/长寿指数UI设计`、`KH503`、管理后台改动、后台接口接入、真实 AI 对话、商品购买流程和设计改版。
- **Architecture Decision**: 已批准将唯一维护的 V2 前端迁移为 Vue 3 + JavaScript，并使用 Vue Router 管理页面导航；不使用 TypeScript。鉴于当前项目以静态方式运行，计划采用 Hash 路由以避免详情刷新依赖服务器回退配置。当前阶段不引入 Pinia、Axios 或 UI 组件库；任何超出该约束的架构变化仍需用户确认。

### Key Entities *(include if feature involves data)*

- **报告**: 表示一次长寿指数报告，包含总分、生理年龄、实际年龄、总体结论和身体系统集合。
- **身体系统**: 表示心血管、肺功能、内分泌、骨骼等报告模块，包含标识、名称、分数、指标、图表数据和建议。
- **健康推荐**: 与特定低分系统及具体问题关联，包含问题描述、方案名称、管理说明、标签和产品展示。
- **报告资源**: 报告中使用的产品图、医生头像、AI 咨询设计图及可下载长图。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首页和七个系统详情的既有内容与交互验收项 100% 通过迁移前后对照检查。
- **SC-002**: 在 320、375、390、768 和 1440 像素视口宽度下，页面均无横向滚动、内容裁切或大段异常留白。
- **SC-003**: 首页打开后 2 秒内完整显示 68 分警示状态、首组健康信息和可操作入口；启用减少动态效果时无需等待动画即可完整显示。
- **SC-004**: 内分泌、睡眠方案、骨骼、钙流失方案四个重点模块的相对顺序和关联关系在全部验收视口中保持正确。
- **SC-005**: 七个系统从首页进入详情后的系统名称、分数和指标数据一致率达到 100%。
- **SC-006**: 内分泌与骨骼详情均展示且仅展示各自匹配的推荐；其余五个系统不出现无关推荐。
- **SC-007**: AI 咨询入口和保存报告操作各能在一次点击内触发目标行为，并提供可感知的结果或回退提示。
- **SC-008**: 在模拟数据模式下浏览首页和全部详情，不发生任何远程业务接口请求。

## Assumptions

- 当前 V2 页面、模拟数据和本地资源是迁移验收的视觉与行为基准。
- 本阶段不调整文案、分数、指标值、产品方案或视觉设计。
- 当前报告只展示女性专项模块，男性专项展示逻辑不在本阶段扩展。
- AI 长寿咨询继续使用已有静态设计内容，不实现聊天会话。
- 保存报告继续下载已生成的 V2 长图，不在本阶段实现浏览器内实时截图生成。
- 后台数据接入将作为独立后续功能进行规格设计。
