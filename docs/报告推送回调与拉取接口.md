# 报告推送、回调与拉取接口文档

**版本**：1.0  
**日期**：2026-11-13  
**适用范围**：检测设备回调、海王侧报告推送/拉取、后台管理端推送记录  
**权威实现**：`nepstarAdmin/backend`；契约细则见 `specs/008-report-push-and-callback/contracts/`

---

## 0. 接口清单

| 接口 | 方法 | 路径 | 鉴权 | 调用方 |
|------|------|------|------|--------|
| 设备检测完成回调 | POST | `/api/v1/report-callback/device` | 无签名（部署层 IP 限制） | 检测设备 |
| 客户主动拉取报告 | GET | `/api/v1/open/reports` | 海王 appKey + 签名 | 海王开放平台 |
| 接收我方推送 | POST | 由海王提供，配置在 `HAIXIN_PUSH_URL` | 海王签名 | 海王开放平台 |
| 后台人工再次推送 | POST | `/api/v1/reports/{report_id}/push` | 管理端 JWT | 后台运营 |
| 后台推送记录列表 | GET | `/api/v1/reports/push-records` | 管理端 JWT | 后台运营 |
| 后台按记录重发 | POST | `/api/v1/reports/push-records/{log_id}/repush` | 管理端 JWT | 后台运营 |

**环境地址**：生产/测试域名以部署配置为准。示例使用 `https://<host>`。

> 管理端接口的 `code` 是**数字**；海王拉取接口的 `code` 是**字符串**（`"0"` 表示成功），两者不要混用。

## 1. 设备检测完成回调

### 1.1 请求

```http
POST /api/v1/report-callback/device
Content-Type: application/json
```

设备检测完成后调用。**不需要签名**，请由部署方在网关层限制来源 IP 并做频控。

```json
{
  "reportId": "KH503LS0005835V261106093253957",
  "deviceId": "KH503LS0005835V",
  "h5Url": "http://kj101.jiankangzhan.com/common.html?reportId=KH503LS0005835V261106093253957&customerId=15418089&middlePage=false",
  "appCustomerInfo": "{\"age\":\"45\",\"appCustomerId\":\"1765248003014\",\"height\":\"163\",\"mobile\":\"28982108221\",\"sex\":\"1\",\"userName\":\"袁勇\",\"weight\":\"22\"}",
  "printH5": "http://kj101.jiankangzhan.com/print/print151.html?reportId=KH503LS0005835V261106093253957&viewType=2",
  "modelType": 30,
  "exceptionTab": "[{\"key\":\"107\",\"value\":\"2\"},{\"key\":\"126\",\"value\":\"2\"}]",
  "customerType": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `reportId` | string | 是 | 报告编号，后台据此定位报告并做幂等 |
| `deviceId` | string | 是 | 设备 SN，辅助校验 |
| `h5Url` | string | 否 | 仅接收，不参与定位；报告链接由后台重新生成 |
| `appCustomerInfo` | string/object | 否 | 仅接收；其中的姓名/手机号等**不会**写入数据库或日志 |
| `printH5` | string | 否 | 仅接收 |
| `modelType` | int | 否 | 仅接收 |
| `exceptionTab` | string/array | 否 | 仅接收 |
| `customerType` | int | 否 | 仅接收 |

未知字段会被忽略，不会导致请求失败。

### 1.2 响应

已受理（立即返回，客户推送在后台异步执行）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "accepted": true,
    "duplicate": false
  },
  "timestamp": 1794527926774
}
```

| 字段 | 说明 |
|------|------|
| `accepted` | 固定 `true`，表示回调已受理 |
| `duplicate` | `true` 表示同一 `reportId` 已有处理中的自动记录、已成功/已跳过记录，或已达到失败尝试上限；本次未新建投递 |

非法请求（缺少 `reportId`/`deviceId`、非法 JSON、类型错误）：

```json
{
  "code": 400,
  "message": "callback.invalid",
  "data": null,
  "timestamp": 1794527926774
}
```

### 1.3 处理规则

1. 后台先写入推送记录并**立即应答**，不等待海王接口；
2. 异步定位报告：首次立即查，失败后按 10s / 20s / 30s 重试；
3. 报告不存在或无效：推送记录标记失败，可在后台“推送记录”页看到并人工重发；
4. 同一 `reportId` 的重复回调不会重复成功推送；
5. 同一 `reportId` 的自动失败记录达到上限（默认 3 条）后，后续回调只应答不再新建记录；
6. 人工“再次推送”不受上述上限限制。

## 2. 客户主动拉取报告

### 2.1 请求

```http
GET /api/v1/open/reports?appKey={appKey}&timestamp={timestamp}&version=1.0&startDate=2026-11-06&endDate=2026-11-13&page=1&pageSize=50&sign={sign}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `appKey` | string | 是 | 海王分配的接入标识 |
| `timestamp` | long | 是 | 10 位秒级时间戳，GMT+8，允许误差 ±10 分钟 |
| `version` | string | 是 | 固定 `1.0` |
| `sign` | string | 是 | 签名结果 |
| `startDate` | string | 否 | `YYYY-MM-DD`，GMT+8，含当天；默认取 `endDate - (N-1)` 天，N 为 `HAIXIN_PULL_DEFAULT_DAYS`（默认 1，即当天） |
| `endDate` | string | 否 | `YYYY-MM-DD`，GMT+8，含当天；默认今天 |
| `page` | int | 否 | 默认 1 |
| `pageSize` | int | 否 | 默认 50，上限 100；超过 100 按 100 返回 |

**区间规则**

- 起止日期均按 GMT+8 自然日解释，查询 `startDate 00:00:00` 至 `endDate 23:59:59`；
- 只返回 `status = 1` 的有效报告；
- 最大跨度 31 天；`startDate > endDate` 或超过 31 天返回 `400`；
- 不传 `endDate` 时取今天；不传 `startDate` 时取 `endDate - (N-1)` 天（N 为默认天数，N=1 即当天）；
- 只传 `startDate` 时，`endDate` 取今天；若因此超过 31 天，返回 `400`。

### 2.2 签名算法

1. 取全部**非空**参数（不含 `sign`、字节类型、空字符串），按参数名 **ASCII 升序**排列；
2. 拼接为 `a=v1&b=v2`；
3. 末尾追加 `&secret=<secret>`；
4. 对整串做 **MD5**，取大写十六进制；
5. 对**大写 MD5 字符串**做 **SHA1**，取大写十六进制，即为 `sign`；
6. 签名基于参数**原始值**计算，URL 编码只用于传输。

> **重要**：签名必须覆盖你实际发送的全部参数。若省略 `page`/`pageSize`/`startDate`/`endDate`，则签名中也不包含它们；若发送，则必须一并签名。

文档黄金示例：

```text
参数：appKey=test&phone=13798261307&timestamp=1547795196&type=1&version=1.0
拼接：appKey=test&phone=13798261307&timestamp=1547795196&type=1&version=1.0&secret=test
MD5 ：F7EB1EA5D9BD607CAFC4600B03F9811A
SHA1：5F366AE0295C45AE78B11FC022199FBB0E5D4239
```

Python 示例：

```python
import hashlib, time, urllib.parse

APP_KEY = "your-app-key"
SECRET = "your-secret"

params = {
    "appKey": APP_KEY,
    "timestamp": str(int(time.time())),
    "version": "1.0",
    "startDate": "2026-11-06",
    "endDate": "2026-11-13",
    "page": "1",
    "pageSize": "50",
}

def sign(p: dict) -> str:
    items = sorted((k, v) for k, v in p.items() if v not in (None, ""))
    s2 = "&".join(f"{k}={v}" for k, v in items) + f"&secret={SECRET}"
    md5_upper = hashlib.md5(s2.encode()).hexdigest().upper()
    return hashlib.sha1(md5_upper.encode()).hexdigest().upper()

params["sign"] = sign(params)
print("https://<host>/api/v1/open/reports?" + urllib.parse.urlencode(params))
```

### 2.3 成功响应

HTTP 200：

```json
{
  "code": "0",
  "message": "success",
  "data": "{\"records\":[{\"report_id\":123456,\"report_code\":\"KH503LS0005835V261106093253957\",\"customer_id\":15418089,\"device_sn\":\"KH503LS0005835V\",\"device_name\":\"检测仪-A\",\"inspect_date\":\"2026-11-06T10:32:53\",\"total_score\":82,\"status\":1,\"status_text\":\"有效\",\"name\":\"袁勇\",\"mobile\":\"13812345678\",\"report_url\":\"http://kj101.jiankangzhan.com/common.html?reportId=KH503LS0005835V261106093253957&customerId=15418089&middlePage=false&realName=1\"}],\"total\":1,\"page\":1,\"pageSize\":50,\"startDate\":\"2026-11-06\",\"endDate\":\"2026-11-13\"}"
}
```

`data` 是 **JSON 字符串**，需二次解析。解析后：

| 字段 | 类型 | 说明 |
|------|------|------|
| `records` | array | 报告列表 |
| `records[].report_id` | int | 后台报告 ID |
| `records[].report_code` | string | 报告编号 |
| `records[].customer_id` | int | 客户编号 |
| `records[].device_sn` | string | 设备 SN |
| `records[].device_name` | string | 设备名称 |
| `records[].inspect_date` | string | 检测时间，ISO 格式（GMT+8） |
| `records[].total_score` | int | 综合得分 |
| `records[].status` | int | 1 有效 |
| `records[].status_text` | string | 有效 |
| `records[].name` | string | 受检者姓名（完整） |
| `records[].mobile` | string | 手机号（完整） |
| `records[].report_url` | string | 报告展示链接 |
| `total` | int | 总记录数 |
| `page` / `pageSize` | int | 当前页与页大小 |
| `startDate` / `endDate` | string | 实际查询区间 |

### 2.4 失败响应

HTTP 状态码均为 200，通过字符串 `code` 判断：

```json
{ "code": "401", "message": "unauthorized", "data": null }
```

| `code` | `message` | 场景 |
|--------|-----------|------|
| `"400"` | `invalid params` | 参数缺失、日期格式错误、区间倒置、超过 31 天 |
| `"401"` | `unauthorized` | appKey 未知/停用、签名错误、时间戳超限、version 不支持 |
| `"503"` | `report data unavailable` | 报告数据源暂时不可用 |

失败响应不返回任何报告数据、堆栈或内部标识。

### 2.5 凭据轮换

服务端支持同时登记新旧 appKey：

- 出站推送使用主 `HAIXIN_APP_KEY` / `HAIXIN_APP_SECRET`；
- 拉取验签使用主凭据 + `HAIXIN_APP_KEYS`（JSON `{appKey: secret}`）合并后的映射；
- 旧 key 从配置移除后，其请求立即返回 `401`。

## 3. 海王侧接收我方推送

> 本节描述**我方调用贵方接口**的请求格式。正式路径、字段名以联调确认为准；后台已做配置化，不需要改代码。

### 3.1 请求

```http
POST {HAIXIN_PUSH_URL}
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 默认字段名 | 说明 |
|------|-----------|------|
| 系统参数 | `appKey` | 我方 appKey |
| 系统参数 | `timestamp` | 10 位秒级时间戳 |
| 系统参数 | `version` | `1.0` |
| 系统参数 | `sign` | 签名，算法同第 2.2 节 |
| 报告编号 | `reportId` | 报告编号 |
| 客户编号 | `customerId` | 客户编号 |
| 设备 SN | `deviceSn` | 设备 SN |
| 检测时间 | `inspectDate` | `YYYY-MM-DD HH:MM:SS`（GMT+8） |
| 综合得分 | `totalScore` | 整数 |
| 报告链接 | `reportUrl` | 报告展示链接 |

示例表单体：

```text
appKey=test&timestamp=1794527926&version=1.0&reportId=KH503LS0005835V261106093253957&customerId=15418089&deviceSn=KH503LS0005835V&inspectDate=2026-11-06%2010%3A32%3A53&totalScore=82&reportUrl=http%3A%2F%2F...&sign=5F366AE0295C45AE78B11FC022199FBB0E5D4239
```

- 不包含姓名、手机号、检测明细或报告文档；
- 值为空时该字段可能不传，签名也相应不包含；
- 字段名可通过 `HAIXIN_PUSH_FIELD_MAP` 覆盖，例如 `{"report_code":"reportNo"}`；
- 超时 5 秒，不自动重试；失败由运营在推送记录页人工重发。

### 3.2 成功判定

- HTTP 状态码 2xx；且
- 响应体为 JSON，`code` 为 `"0"` 或 `0`。

任一不满足即视为失败。失败原因会记录在后台推送记录中：

| `failure_reason` | 含义 |
|------------------|------|
| `delivery.config_missing` | 未配置推送地址或凭据 |
| `delivery.disabled` | 推送功能未启用 |
| `delivery.timeout` | 客户接口超时 |
| `delivery.network` | 连接失败/HTTP 非 2xx |
| `delivery.rejected` | 客户返回业务码非 0 |
| `delivery.bad_response` | 客户响应不是约定 JSON |
| `delivery.interrupted` | 进程重启导致投递中断 |

## 4. 后台管理接口（内部）

### 4.1 人工再次推送

```http
POST /api/v1/reports/{report_id}/push
Authorization: Bearer {token}
```

同步等待客户接口，最长约 5 秒。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "record_id": 1024,
    "status": "success",
    "failure_reason": null
  },
  "timestamp": 1794527926774
}
```

- 投递失败仍返回 `code = 200`，此时 `data.status = "failed"`，`data.failure_reason` 为第 3.2 节的原因；
- 未产生投递的拒绝：

| `code` | `message` | 场景 |
|--------|-----------|------|
| 404 | `report.not_found` | 报告不存在 |
| 403 | `report.forbidden` | 报告不在当前用户组织数据范围内 |
| 409 | `report.invalid` | 报告无效或缺少报告编号/客户编号 |
| 503 | `report.unavailable` | 旧库报告数据暂不可用 |

### 4.2 推送记录列表

```http
GET /api/v1/reports/push-records?page=1&page_size=20&start_date=2026-11-01&end_date=2026-11-13&status=failed&trigger_type=auto&sn=KH503
Authorization: Bearer {token}
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `page` | 否 | 默认 1 |
| `page_size` | 否 | 默认 20，上限 100 |
| `start_date` / `end_date` | 否 | 按推送时间过滤，GMT+8，含当天 |
| `status` | 否 | `pending` / `success` / `failed` / `skipped` |
| `trigger_type` | 否 | `manual` / `auto` |
| `sn` | 否 | 设备 SN 模糊匹配 |

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "id": 1024,
        "report_id": 123456,
        "report_code": "KH503LS0005835V261106093253957",
        "device_sn": "KH503LS0005835V",
        "trigger_type": "auto",
        "operator_id": null,
        "status": "failed",
        "failure_reason": "delivery.timeout",
        "response_summary": "HTTP 200 code=... message=...",
        "created_at": "2026-11-13T10:00:00",
        "finished_at": "2026-11-13T10:00:05"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

- 只返回当前用户有权查看的报告对应记录；
- 不含完整姓名/手机号、secret 或签名原文。

### 4.3 按记录重发

```http
POST /api/v1/reports/push-records/{log_id}/repush
Authorization: Bearer {token}
```

- 按记录中的 `report_code` 重新推送；
- 新增一条 `trigger_type = "manual"` 的记录，原记录保留；
- 响应同 4.1；报告无效/越权同样返回 409/403。

## 5. 配置项（部署端）

以下配置只放在服务器 `.env`，不写入仓库、不返回前端：

| 配置 | 默认 | 说明 |
|------|------|------|
| `HAIXIN_APP_KEY` | 空 | 主 appKey（出站推送使用） |
| `HAIXIN_APP_SECRET` | 空 | 主 secret |
| `HAIXIN_APP_KEYS` | `{}` | JSON `{appKey: secret}`，拉取验签新旧并存 |
| `HAIXIN_PUSH_URL` | 空 | 海王报告接收地址 |
| `HAIXIN_PUSH_ENABLED` | `false` | 关闭时只记录失败，不发起外发 |
| `HAIXIN_PUSH_METHOD` | `POST` | `POST`（表单）或 `GET` |
| `HAIXIN_PUSH_TIMEOUT_SECONDS` | `5.0` | 单次投递超时 |
| `HAIXIN_PUSH_FIELD_MAP` | `{}` | 出站字段名映射 |
| `HAIXIN_SIGN_TOLERANCE_SECONDS` | `600` | 拉取时间戳容差 |
| `HAIXIN_PULL_DEFAULT_DAYS` | `1` | 拉取默认天数 |
| `HAIXIN_PULL_MAX_DAYS` | `31` | 拉取最大天数 |
| `HAIXIN_PULL_DEFAULT_PAGE_SIZE` | `50` | 默认页大小 |
| `HAIXIN_PULL_MAX_PAGE_SIZE` | `100` | 最大页大小 |
| `HAIXIN_AUTO_MAX_FAILED_ATTEMPTS` | `3` | 同一报告自动失败上限 |

## 6. 安全与注意事项

1. **拉取接口返回完整姓名/手机号**，只能通过 HTTPS 暴露；网关不要记录该路径的查询串与响应体。
2. **回调接口按本期决定不做签名**，必须由网关限制设备出口 IP 并做频控；否则任何可达来源都能写入失败推送记录。
3. 服务端日志不记录 secret、完整签名串、完整姓名/手机号或拉取响应体。
4. 时间统一使用 GMT+8；时间戳为 10 位秒级 Unix 时间戳。
5. 同一 `reportId` 的重复回调不会重复成功推送；人工重发始终执行。
6. 推送记录页沿用“检测报告”的组织数据范围；非管理员角色需要单独授予 `view`/`add` 权限。
