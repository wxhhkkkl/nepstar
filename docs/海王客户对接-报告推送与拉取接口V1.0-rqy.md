# 报告推送与拉取接口文档（客户对接版）

**版本**：1.0  
**日期**：2026-11-13  
**对接方**：海王开放平台  
**交互方向**：我方推送报告给贵方；贵方按时间范围主动拉取报告

---

## 1. 对接概览

本次对接包含两个方向，共用同一套 appKey/secret 与签名规则：

| 方向 | 接口 | 调用方 | 被调用方 |
|------|------|--------|----------|
| 我方 → 贵方 | 接收报告推送 | 我方 | 贵方开放平台 |
| 贵方 → 我方 | 主动拉取报告 | 贵方开放平台 | 我方报告服务 |

**签名规则一致**：系统参数 `appKey`、`timestamp`、`version`、`sign` + 业务参数，按参数名 ASCII 升序拼接后做 MD5→SHA1（均取大写）。

---

## 2. 公共约定

### 2.1 地址

| 用途 | 地址 |
|------|------|
| 我方拉取接口 | `https://<NEPSTAR_API_HOST>/api/v1/open/reports` |
| 我方接收方 | 贵方提供的报告接收地址 |

`<NEPSTAR_API_HOST>` 在联调前由双方确认。

### 2.2 系统参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `appKey` | string | 是 | 贵方分配的接入标识 |
| `timestamp` | long | 是 | 10 位秒级 Unix 时间戳，GMT+8；允许误差 ±10 分钟 |
| `version` | string | 是 | 固定 `1.0` |
| `sign` | string | 是 | 签名结果，大写 |

### 2.3 签名算法

以“所有非空参数”为输入：

1. 去掉 `sign`、空值、字节类型参数；
2. 参数名按 **ASCII 升序**排列；
3. 拼接为 `a=v1&b=v2`；
4. 末尾追加 `&secret=<secret>`；
5. 对整串做 **MD5**，取大写十六进制；
6. 对**大写 MD5 字符串**做 **SHA1**，取大写十六进制，即为 `sign`；
7. 签名基于参数**原始值**计算，URL 编码仅用于传输。

文档标准示例：

```text
参数：appKey=test&phone=13798261307&timestamp=1547795196&type=1&version=1.0
拼接：appKey=test&phone=13798261307&timestamp=1547795196&type=1&version=1.0&secret=test
MD5 ：F7EB1EA5D9BD607CAFC4600B03F9811A
SHA1：5F366AE0295C45AE78B11FC022199FBB0E5D4239
```

Python 参考实现：

```python
import hashlib

def build_sign(params: dict, secret: str) -> str:
    items = sorted(
        (k, v) for k, v in params.items()
        if k != "sign" and v not in (None, "")
    )
    source = "&".join(f"{k}={v}" for k, v in items) + f"&secret={secret}"
    md5_upper = hashlib.md5(source.encode("utf-8")).hexdigest().upper()
    return hashlib.sha1(md5_upper.encode("utf-8")).hexdigest().upper()
```

> **注意**：签名必须覆盖实际发送的全部参数。省略的参数不参与签名；发送了就必须签名。

## 3. 接口一：接收我方报告推送

**方向**：我方 → 贵方  
**地址**：由贵方提供，双方在联调前确认  
**方法**：`POST`  
**Content-Type**：`application/x-www-form-urlencoded`

### 3.1 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `appKey` | string | 是 | 贵方分配给我方的 appKey |
| `timestamp` | long | 是 | 10 位秒级时间戳 |
| `version` | string | 是 | `1.0` |
| `sign` | string | 是 | 我方按第 2.3 节生成 |
| `reportId` | string | 是 | 报告编号 |
| `customerId` | string | 是 | 客户编号 |
| `deviceSn` | string | 否 | 设备 SN，可能为空 |
| `inspectDate` | string | 是 | 检测时间，`YYYY-MM-DD HH:MM:SS`（GMT+8） |
| `totalScore` | int | 否 | 综合得分，可能为空 |
| `reportUrl` | string | 是 | 报告展示链接 |

示例表单体（已 URL 编码）：

```text
appKey=your-app-key&timestamp=1794527926&version=1.0&reportId=KH503LS0005835V261106093253957&customerId=15418089&deviceSn=KH503LS0005835V&inspectDate=2026-11-06%2010%3A32%3A53&totalScore=82&reportUrl=http%3A%2F%2F...&sign=5F366AE0295C45AE78B11FC022199FBB0E5D4239
```

**字段说明**

- 推送内容为报告基础摘要 + 报告链接，**不包含**姓名、手机号、检测明细或报告文档；
- 值为空时该字段可能不传，签名也相应不包含；
- 若贵方接口要求不同字段名或 JSON/GET 形式，请在联调前告知，我方可通过配置映射适配，无需改代码。

### 3.2 成功响应

贵方返回 HTTP 2xx，且响应体为 JSON，`code` 为 `"0"` 或 `0`，即视为推送成功：

```json
{
  "code": "0",
  "message": "success",
  "data": null
}
```

### 3.3 失败与补发

- 贵方返回非 2xx、业务码非 `0`、超时或响应格式不符，我方会记录失败；
- 我方**不自动重复推送**，由运营人员在后台核对后人工补发，避免贵方收到重复报告；
- 补发可能产生同一 `reportId` 的多次推送，请贵方按 `reportId` 幂等处理。

## 4. 接口二：贵方主动拉取报告

**方向**：贵方 → 我方  
**方法**：`GET`  
**地址**：`https://<NEPSTAR_API_HOST>/api/v1/open/reports`

### 4.1 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `appKey` | string | 是 | 贵方分配的 appKey |
| `timestamp` | long | 是 | 10 位秒级时间戳，误差 ≤10 分钟 |
| `version` | string | 是 | `1.0` |
| `sign` | string | 是 | 按第 2.3 节生成 |
| `startDate` | string | 否 | `YYYY-MM-DD`，GMT+8，含当天；默认 `endDate - (N-1)` 天，N 为默认天数（默认 1，即当天） |
| `endDate` | string | 否 | `YYYY-MM-DD`，GMT+8，含当天；默认今天 |
| `page` | int | 否 | 默认 1 |
| `pageSize` | int | 否 | 默认 50，上限 100；超过 100 按 100 返回 |

**区间与分页规则**

- 查询区间为 `startDate 00:00:00` 至 `endDate 23:59:59`（GMT+8）；
- 只返回有效报告（`status = 1`）；
- 最大跨度 31 天；`startDate > endDate` 或超过 31 天返回 `400`；
- 不传 `startDate` 时按默认天数倒推；只传 `startDate` 时 `endDate` 取今天；
- 按检测时间倒序；
- `page`/`pageSize` 若被省略，签名中也不包含；若发送，必须一并签名。

### 4.2 请求示例

```bash
curl -G 'https://<NEPSTAR_API_HOST>/api/v1/open/reports' \
  --data-urlencode 'appKey=<APP_KEY>' \
  --data-urlencode 'timestamp=<10位时间戳>' \
  --data-urlencode 'version=1.0' \
  --data-urlencode 'startDate=2026-11-06' \
  --data-urlencode 'endDate=2026-11-13' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=50' \
  --data-urlencode 'sign=<SIGN>'
```

### 4.3 成功响应

HTTP 200：

```json
{
  "code": "0",
  "message": "success",
  "data": "{\"records\":[{\"report_id\":123456,\"report_code\":\"KH503LS0005835V261106093253957\",\"customer_id\":15418089,\"device_sn\":\"KH503LS0005835V\",\"device_name\":\"检测仪-A\",\"inspect_date\":\"2026-11-06T10:32:53\",\"total_score\":82,\"status\":1,\"status_text\":\"有效\",\"name\":\"袁勇\",\"mobile\":\"13812345678\",\"report_url\":\"http://...\"}],\"total\":1,\"page\":1,\"pageSize\":50,\"startDate\":\"2026-11-06\",\"endDate\":\"2026-11-13\"}"
}
```

> `code` 为**字符串**，`data` 为 **JSON 字符串**，需要二次解析。

解析 `data` 后：

| 字段 | 类型 | 说明 |
|------|------|------|
| `records` | array | 报告列表 |
| `records[].report_id` | int | 后台报告 ID |
| `records[].report_code` | string | 报告编号 |
| `records[].customer_id` | int | 客户编号 |
| `records[].device_sn` | string | 设备 SN |
| `records[].device_name` | string | 设备名称 |
| `records[].inspect_date` | string | 检测时间，ISO 格式（GMT+8） |
| `records[].total_score` | int | 综合得分 |
| `records[].status` | int | 1 = 有效 |
| `records[].status_text` | string | 有效 |
| `records[].name` | string | 受检者姓名（完整） |
| `records[].mobile` | string | 手机号（完整） |
| `records[].report_url` | string | 报告展示链接 |
| `total` | int | 总记录数 |
| `page` / `pageSize` | int | 当前页与页大小 |
| `startDate` / `endDate` | string | 实际查询区间 |

### 4.4 失败响应

HTTP 状态码均为 200，通过字符串 `code` 判断：

```json
{ "code": "401", "message": "unauthorized", "data": null }
```

| `code` | `message` | 场景 |
|--------|-----------|------|
| `"400"` | `invalid params` | 参数缺失、日期格式错误、区间倒置、超过 31 天 |
| `"401"` | `unauthorized` | appKey 未知/停用、签名错误、时间戳超限、version 不支持 |
| `"503"` | `report data unavailable` | 报告数据源暂时不可用 |

失败响应不返回任何报告数据、堆栈或内部标识。

## 6. 安全与数据处理

1. 拉取接口返回完整姓名与手机号，必须仅通过 **HTTPS** 调用；
2. 请勿在日志中记录 `secret`、完整签名串或拉取响应体；
3. 推送与拉取均使用同一套 appKey/secret，请妥善保管，轮换时提前告知；
4. 时间统一使用 GMT+8，时间戳为 10 位秒级 Unix 时间戳；
5. 同一 `reportId` 可能因人工补发被多次推送，请按 `reportId` 幂等处理。
