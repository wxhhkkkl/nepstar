# 长寿指数报告｜二级详情页数据承接说明

> 当前阶段只确定交互、数据与内容规则，不绘制二级详情页设计稿。

## 1. 进入方式

- 用户点击首页任一身体系统卡片，进入该系统对应的二级详情页。
- 路由沿用 `detail.html?id={moduleId}`，例如心血管为 `detail.html?id=cardio`。
- 二级页必须提供明确返回入口；返回首页时保留用户离开前的滚动位置和已播放动画状态。
- 女性功能与男性功能继续依据用户档案互斥展示，只允许进入当前适用的性别专项详情。

## 2. 首页内容如何带入详情页

二级页不是重新创建另一套图表，而是继承首页卡片的视觉标识和数据源：

1. **模块标识**：模块名称、线性图标、序号、状态文案和主题色。
2. **核心结果**：模块活力值、状态等级、关键结论。
3. **核心图表**：保留首页图表类型与识别特征，在详情页放大展示。
4. **指标数据**：复用同一组数值；详情页补充指标全称、权重、单位、采集时间和参考说明。
5. **动效连续性**：后续可采用共享元素过渡，让首页图表自然放大进入详情；同时支持减少动态效果设置。

实现时必须从 `data.js` 的模块对象读取数据，其中 `visualization` 为图表承接契约。禁止分别维护首页数值和详情页数值。

## 4. 二级页内容范围（后续设计依据）

二级页后续设计至少包含以下信息层级，但当前不确定具体版式：

1. 模块标题、图标、分数、状态和一句话结论。
2. 从首页继承并放大的核心图表。
3. 图表数据标签、单位、时间范围、图例及可点击数据点。
4. 详细指标列表：指标名、得分、权重、参考说明。
5. 直接采集结果：如心率、心电图、血氧等；无数据时隐藏整个区块。
6. 指标解读、影响长寿指数的原因和变化趋势。
7. 可执行的改善建议与复测周期。
8. 医疗免责声明：内容用于健康管理参考，不替代诊断。

## 5. 图表与可用性规则

- 图表必须同时展示数字或文字标签，不能只依赖颜色表达结果。
- 趋势图需标注时间范围和单位；对比图需显示类别名与具体值。
- 可交互数据点的有效点击区域不小于 44pt，并提供点击反馈。
- 详情页加载失败或暂无数据时，应出现明确的空状态和重试方式，不能只显示空白坐标轴。
- 返回路径必须稳定，不使用替换历史记录的方式跳转。
- 图表与首页使用同一 `visualization.key`，便于后续实现共享元素过渡和埋点统计。

## 6. 数据契约

每个模块新增以下结构：

```js
visualization: {
  type: "line",
  key: "cardio-trend",
  title: "心血管活力趋势",
  unit: "活力值",
  period: "近 6 次",
  categories: [],
  series: [82, 85, 83, 86, 84, 88],
  carryToDetail: true
}
```

- `type`：图表类型。
- `key`：首页与详情页共用的图表身份标识。
- `title`：详情页主图表标题。
- `unit`：数据单位。
- `period`：时间范围，适用于趋势类数据。
- `categories`：对比维度名称。
- `series`：图表数据。
- `carryToDetail`：是否需要在二级页继承展示。

后续绘制二级详情页前，只需进一步确认时间序列的真实采集日期、参考区间和异常判定文案。
